# Aether Desktop 1.3.0 engineering handoff

- Desktop version: `1.3.0` in npm (`package.json` + `package-lock.json`), Cargo, Tauri (`tauri.conf.json`), Windows manifest, installer fallback, README (EN/FA), release notes, and the CI release tag (`v1.3.0`).
- Engine version: `1.8.0` in root `CORE_VERSION`, vendored `native/aether/CORE_VERSION`, and the `scripts/sync-core.sh` baseline.
- Engine source: exact supplied Aether 1.8.0 tree, including Quiche, vendored under `native/aether`. The move from 1.7.0 was a clean tree replacement (`C:\Prog\Aether-1.8.0` mapped 1:1 onto `native/aether`). Four new test/demo key files land under `quiche/` (`apps/src/bin/cert.key`, `fuzz/cert.key`, `quiche/examples/cert.key`, `tokio-quiche/examples/cert.key`); the `quiche/fuzz/mayhem/*` layout is reproduced as small text stubs (`Mayhemfile` + ~25-35 B `testsuite` files). The rollback snapshot `native/.core-prev/` (gitignored) currently holds the pre-import 1.7.0 tree as the last known-good and is refreshed automatically by `sync-core.sh` on the next manual pin.
- Patch state: still empty at 1.8.0 — `aether/src/prober.rs` and `aether/src/wg_prober.rs` are byte-identical to their `.upstream-baseline` copies (verified by hash), so the three-way rebase in `sync-core.sh` starts clean. The baseline was reseeded from the 1.8.0 files.
- Engine surface versus 1.7.0: no CLI flag or `AETHER_*` environment variable was added or removed (verified by diffing `cli.rs`), so the desktop capability gate does not need a new `CoreCaps` entry and every existing gate keeps its exact condition (`engine_core_version >= (1, 4)` for `--log-level/--perf`, `>= (1, 7)` for upstream/host-match/reprovision). `build-engine.ps1` still resolves the crate through its `native/aether/aether` candidate.
- What 1.8.0 actually changed (internal, no new UI surface): `socks.rs` reworked the stream-head reader used for host-name detection and added unit tests for a head arriving intact/split/with trailing bytes; `lib.rs` tightened endpoint-selection handling (new internal `Winner` enum); small robustness fixes across `aethernoize.rs`, `upstream.rs`, `wireguard.rs`. The desktop contract (argv, env, exit codes, `CORE_VERSION` file) is untouched.
- CI rewritten as four modular jobs (`.github/workflows/build.yml`):
  - `validate` (Ubuntu): required-file list (now includes `scripts/embed-manifest.ps1`, `src-tauri/windows-manifest.xml`, `package-lock.json`), JSON validity (incl. lockfile), `node --check` on every `src/**/*.js`, vendored-core consistency (`BASELINE` == both `CORE_VERSION` files == `Cargo.toml` version, `Cargo.lock` present, no committed `target/` dirs), plus the UAC/manifest/watchdog and no-Proxy-Mode checks.
  - `sync-core` (Ubuntu): opt-in. Steps run only on `workflow_dispatch` with a `core_target` pin or `core_sync=force`; otherwise the job finishes in seconds with `core_changed=false`. Deterministic pushes; no upstream clone and no ~10MB artifact on ordinary runs.
  - `build` (Windows x64/x86 matrix, `timeout-minutes: 75`): conditional download of a pinned core only when `core_changed == 'true'`; `setup-node` with `cache: npm` + `npm ci` on the committed lockfile; `dtolnay/rust-toolchain`; `cargo generate-lockfile` before `rust-cache` (stable cache keys, meaningful `cargo audit`); `rust-cache` now covers **both** workspaces (`src-tauri` + `native/aether/aether`) with `save-if: main/tags`; engine build with rollback + timeouts; unit tests (fail-fast); clippy and audit on x64 only; Tauri build `--no-bundle`; manifest embed; stage/portable/Inno/sign/smoke unchanged.
  - `release` (Ubuntu): unchanged idempotent publish via official `gh` CLI with tag re-pointing and checksum generation.
- Behaviour/watch items:
  - `src-tauri` does not commit a `Cargo.lock`; the lockfile is generated on the runner. A follow-up could commit it for full reproducibility (requires a local `cargo generate-lockfile` once).
  - `npm ci` now succeeds because `package-lock.json` was regenerated and committed (`npm install --package-lock-only` after the version bump).
  - Frontend build intentionally remains inside the Windows jobs (`--no-before-build` does not exist in the installed Tauri CLI 2), so the `web:build` step still runs per architecture.
  - Clippy/audit run on x64 only to halve cost; the engine compile (boring/quiche) is now covered by `rust-cache`.
- Profile compatibility: no `ConnectionProfile` changes in this release; existing `profile.json` files load unchanged and default argv/env stay byte-identical.
- Validation performed before commit: YAML parsed and jobs/matrix/needs verified; `node --check` on all frontend JS; `npm.cmd run web:build` verified against the new lockfile; core tree replacement verified (Cargo.toml `1.8.0`, both `CORE_VERSION` files `1.8.0`, `Cargo.lock` present, `cert.key` set correct); version bumps across all metadata sites. Native Windows binaries and `cargo test` must still be produced by the repository's Windows CI matrix (Rust is not installed locally).
